## 1. Цель

Вместо одной формы с пикером университета — мастер из шести шагов, который приводит студента
сразу в свою группу и к расписанию, без ручного назначения группы администратором.

| # | Шаг | Что выбирает | Зависит от |
|---|---|---|---|
| 1 | Личные данные | логин, имя, фамилия, email, пароль, дата рождения | — (экран уже есть) |
| 2 | Регион | регион РФ | — |
| 3 | Университет | ВУЗ выбранного региона | регион |
| 4 | Факультет | факультет выбранного ВУЗа | университет |
| 5 | Курс | 1–5 | факультет |
| 6 | Группа | группа факультета на выбранном курсе | факультет + курс |

**Главное требование:** на любом шаге со 2-го по 6-й нужной сущности может не оказаться.
Студент не должен упираться в тупик — см. раздел 4.

Регистрация преподавателя в этот спринт не входит (см. открытый вопрос 6.4).

## 2. Что есть сейчас

**Приложение**
- `RegisterStudentScreen` — одна форма: личные данные + поиск университета по всей стране
  (`SearchableSelectField`, `useUniversitiesQuery`) → `POST /students/register`.
- После регистрации приложение само входит под новым пользователем (`loginWithPassword`) и
  открывает профиль. Значит, шаги после первого могут выполняться уже с токеном.
- Профиль студента без группы показывает «Группа ещё не назначена. Обратитесь к администратору».

**Бэкенд — что мешает мастеру**
- **Регионы уже есть (issue #80 бэкенда).** `GET /regions` — публичный справочник 89 субъектов
  РФ, `GET /universities?regionId=` — фильтр, `regionId` обязателен у каждого ВУЗа. В регионе
  может не быть ни одного ВУЗа.
- **Много ВУЗов без факультетов** (87 из первых 200) — пустой шаг 4 будет частым случаем, а не
  исключением.
- **Группа не привязана к факультету напрямую.** Цепочка: группа → семестр → учебный год
  (`yearNumber` — это и есть «курс») → программа → факультет. Шага «программа» в мастере нет,
  поэтому «группы факультета на N-м курсе» — это обход всех программ факультета.
- **Справочники ниже факультета закрыты.** `programs`, `study-years`, `semesters`, `groups`
  без токена отвечают `401`; публичны только университеты, факультеты и кафедры.
- **Студент не может сам выбрать группу.** `RegisterStudentRequest` не принимает `groupId`,
  а `PUT /students/{id}` доступен только `ADMIN`.
- **`universityId` обязателен при регистрации** — зарегистрироваться, не найдя свой ВУЗ, нельзя.
- **Факультет и курс негде хранить.** У `StudentDto` есть только `universityId` и `groupId`;
  если группы нет, выбранные факультет и курс теряются.

## 3. Ключевое решение: когда создаётся аккаунт

**Рекомендация — аккаунт создаётся на шаге 1, шаги 2–6 идут уже под токеном.**

1. Шаг 1 → `POST /students/register` (без университета) → автовход.
2. Шаги 2–6 — «настройка профиля»: каждый выбор сохраняется на сервере.
3. Пока профиль не заполнен, приложение при входе открывает мастер с первого незаполненного шага.

Почему так:
- **Отсутствующая сущность перестаёт быть проблемой регистрации.** Аккаунт уже есть, профиль
  валиден при любой степени заполненности, мастер можно продолжить позже.
- **Занятый логин или email (`409`) виден сразу**, а не после шести экранов.
- **Закрытые справочники не нужно открывать публично** — под токеном они уже доступны.
- **Переживает закрытие приложения** — прогресс хранится на сервере, а не в памяти.

Цена: появляются аккаунты с незаполненным профилем, и нужно снять обязательность `universityId`.

Альтернатива — копить выбор локально и отправить один запрос в конце. Тогда нужно открыть
публично все справочники до групп, добавить `groupId` в `RegisterStudentRequest`, а случай
«сущности нет» всё равно потребует необязательных полей. Выигрыша не даёт.

## 4. Отсутствующие сущности

### 4.1. Какие бывают «нет»

| Вид | Пример | Как отличить |
|---|---|---|
| **Список пуст** | у ВУЗа нет факультетов; на 3-м курсе нет групп | `200` и `totalElements == 0` |
| **Нужного нет в списке** | факультет есть, но не мой | решает пользователь: «Нет в списке» |
| **Регион без ВУЗов** | в справочнике 89 регионов, ВУЗы есть не в каждом | `200` и пустой список на шаге 3 |
| **Не знаю / позже** | первокурсник ещё не знает группу | кнопка «Пропустить» |
| **Ошибка загрузки** | нет сети, `5xx` | **не** пустой список — экран ошибки с «Повторить» |
| **Сущность исчезла** | группу удалили между выбором и сохранением | `404`/`422` при сохранении |

Пустой список и ошибка загрузки обязаны выглядеть по-разному: сейчас часть экранов при сбое
показывает просто пустоту, здесь это привело бы к ложному «вашего ВУЗа нет».

### 4.2. Общее правило

Шаги зависят друг от друга по цепочке, поэтому **если на шаге N сущности нет — шаги N+1…6
пропускаются**, а не показываются пустыми:

1. Сохраняется всё выбранное до шага N−1.
2. Студент попадает на финальный экран, где сказано, чего именно не хватает и что будет дальше.
3. В профиле появляется карточка «Завершить настройку», которая открывает мастер с шага N.
4. По желанию студент оставляет заявку: «Моего факультета нет — ФКТИ» (свободный текст).

На каждом шаге 2–6 одинаковый набор действий: выбрать из списка, «Нет в списке», «Пропустить»,
«Назад».

### 4.3. По шагам

| Шаг | Нет сущности, когда… | Что показываем | Что сохранено | Куда дальше |
|---|---|---|---|---|
| 2. Регион | региона нет в списке; список не загрузился | «Нет в списке» → поиск ВУЗа по всей стране | ничего | шаг 3 без фильтра по региону |
| 3. Университет | в регионе нет ВУЗов; моего нет; ВУЗ привязан к другому региону | пустое состояние + «Искать по всем регионам» + «Нет в списке» | регион | поиск по стране → шаг 4, либо финал |
| 4. Факультет | у ВУЗа нет факультетов; моего нет | «В этом ВУЗе пока нет факультетов» + заявка | регион, ВУЗ | финал |
| 5. Курс | на факультете нет программ или учебных годов | курсы без групп помечены; выбрать можно любой | регион, ВУЗ, факультет | шаг 6 (возможно, пустой) |
| 6. Группа | на курсе нет групп; моей нет; не знаю группу | «Групп пока нет» + заявка | всё, кроме группы | финал |

Отдельные случаи:
- **Регион — единственный шаг, где «нет» не останавливает мастер.** Регион нужен только как
  фильтр, поэтому без него шаг 3 превращается в нынешний поиск по всей стране. Этим же
  закрывается случай, когда ВУЗ привязан не к тому региону, где его ищет студент.
- **Курс выбирается всегда из 1–5**, даже если учебных годов в данных нет: это знание самого
  студента, оно пригодится администратору при назначении группы.
- **Смена выбора выше по цепочке сбрасывает всё ниже.** Вернулся на шаг 3 и сменил ВУЗ —
  факультет, курс и группа очищаются, в том числе на сервере.
- **Сущность исчезла при сохранении** — возврат на этот шаг с сообщением и перезагрузкой списка,
  а не общий тост об ошибке.

### 4.4. Финальный экран и профиль

Финал зависит от того, докуда дошёл студент:

| Заполнено до | Заголовок | Текст |
|---|---|---|
| группы | «Готово» | сразу открывается расписание |
| курса | «Почти готово» | «Группа появится, когда её добавит администратор» |
| ВУЗа | «Профиль создан» | «Факультета пока нет в списке — мы сообщим администратору» |
| ничего | «Профиль создан» | «Вашего ВУЗа пока нет в списке» |

Текущий текст профиля «Обратитесь к администратору» заменяется на карточку «Завершить
настройку» с указанием первого незаполненного шага. Когда недостающая сущность появится на
бэкенде, студент доходит мастер сам — без администратора.

## 6. Открытые вопросы

1. ✅ **Решено (2026-10-08): студент может сам записаться в любую группу**, без подтверждения
   администратором.
2. ✅ **Решено на бэкенде (univer#83):** семестр, который идёт сейчас; на каникулах — ближайший
   будущий; если будущих нет — последний закончившийся.
3. **Курс 1–5 или по факту?** В магистратуре курсов два, у специалитета бывает шесть. Жёстко
   1–5 или диапазон из учебных годов факультета? Бэкенд с univer#86 принимает `yearNumber`
   от 1 до 6; мастер пока предлагает 1–5.
4. **Преподаватель.** Нужен ли ему такой же мастер (регион → ВУЗ → факультет → кафедра)?
   Сейчас форма не отправляет `departmentId`, хотя `API.md` называет его обязательным, —
   регистрация при этом проходит.
5. ✅ **Решено (2026-10-08): заявки не будет — студент сам создаёт недостающую сущность**
   (шаги X и Y, раздел 9). С 2026-10-09 это не касается университета: его студент не создаёт,
   а оставляет заявку на добавление (B13 + M15, сценарий 1 в разделе 8).
6. ✅ **Сделано:** да, через «Изменить университет или группу» в профиле (мастер с шага 2).

## 8. Сценарии регистрации студента

Пять сквозных сценариев — от шага 1 до того, что студент видит в конце. Во всех пяти шаг 1
одинаков: студент заполняет личные данные, аккаунт создаётся, приложение входит под ним и само
открывает шаг 2. Дальше сценарии расходятся по тому, на каком звене цепочки заканчиваются данные.

| # | Где обрывается | Что сохранено в профиле | Финальный экран | Что дальше |

| 5 | не обрывается | всё | «Готово» | экран расписания с занятиями |

«Проверено» ниже — прогон на эмуляторе 2026-10-08 на локальном стенде.

расписан по целевому поведению: университет студент не создаёт, а оставляет заявку.

### Сценарий 1. Выбрал регион, но в нём нет университетов

Университет студент не создаёт (9.3) — вместо этого он оставляет **заявку на добавление
университета** (решение 2026-10-09). Ниже — целевое поведение; что из него уже работает, см.
«Расхождения с текущим поведением» в конце сценария.

**Шаг 2 «Регион».**
1. Студент выбирает регион (на стенде без университетов — Ненецкий автономный округ и
   Херсонская область). На этом шаге ничего не сохраняется: регион только фильтрует список.
2. Другие выходы с шага: «Моего региона нет в списке» → шаг 3 без фильтра; «Выберу университет
   позже» → финал «Профиль создан».

**Шаг 3 «Университет», фильтр по региону.**
3. Подзаголовок «Регион: …». Вместо списка — «В этом регионе пока нет университетов»,
   подсказка «Возможно, университет привязан к другому региону — попробуйте поиск по всем
   регионам» и кнопка «Искать по всем регионам». Та же ссылка стоит в подвале: «Нет в списке —
   искать по всем регионам». «Далее» неактивна.
4. «Искать по всем регионам» снимает фильтр на том же экране: подзаголовок «Поиск по всем
   регионам», список всех университетов с поиском по названию. Выбранный на шаге 2 регион
   приложение помнит до конца мастера — он подставится в заявку.
5. Университет нашёлся → «Далее» → `PATCH /students/me` с `universityId` → шаг 4, дальше
   сценарии 2–5.

**Заявка.**
6. Университет не нашёлся → ссылка в подвале «Моего университета нет в списке» открывает форму
   «Заявка на добавление университета»:

   | Поле | Обязательное | Откуда |
   |---|---|---|
   | Название университета | да, до 255 символов | вводит студент; подставляется текст из поиска шага 3 |
   | Регион | нет | подставлен из шага 2; если студент пришёл без региона — выбирается в форме или остаётся пустым |

   Над формой — пояснение: «Университеты добавляет администратор. Оставьте заявку — мы добавим
   ваш университет, и вы продолжите настройку».
7. «Отправить заявку» → `PUT /students/me/university-request` (B13; `regionId` передаётся
   всегда — не переданный очищается) → финал «Заявка отправлена»: «Мы добавим
   «<название>» в список. Продолжить настройку можно будет из профиля». Кнопка «Перейти в
   профиль».
8. «Завершить без заявки» на форме → прежний финал «Профиль создан»: «Университет не выбран».
   «Назад» с формы возвращает на шаг 3 с тем же поиском.

**Заявка при уже выбранном университете.** Через «Изменить университет или группу» до формы
доходит студент, у которого университет в профиле есть. Сервер такую заявку не принимает
(`422`), поэтому перед отправкой приложение показывает подтверждение: «Текущий университет,
факультет, курс и группа будут сброшены». После согласия — `PATCH /students/me` с
`universityId: null`, затем заявка. Расписания у студента нет, пока заявку не закроют.

**После мастера.**
9. В профиле: «Университет: не выбран»; карточка «Завершить настройку — выберите университет»
   открывает шаг 2. Заявку приложение читает через `GET /students/me/university-request`
   (`404` — заявок не было, это не ошибка). Для `PENDING` в карточке вместо общего текста —
   «Заявка на «<название>» отправлена», для `REJECTED` — «Заявка на «<название>» отклонена».
   `COMPLETED` при пустом университете (студент позже сам его снял) — как будто заявки нет.
10. Когда администратор добавил университет по заявке, сервер сам проставляет его в профиль
    студента (если университет в профиле всё ещё пуст). При следующем запуске мастер открывается
    на шаге 4 «Факультет» — дальше сценарий 2.
11. На экране расписания — «Вы ещё не выбрали группу» и та же кнопка, что в карточке.

**Ошибки.**
- Список регионов не загрузился → экран ошибки с «Повторить»; ссылка в подвале — «Искать
  университет по всем регионам».
- Список университетов не загрузился → экран ошибки с «Повторить», а не пустое состояние — иначе
  студент получит ложное «в регионе нет университетов» и отправит лишнюю заявку.
- Ошибка отправки заявки → форма остаётся заполненной, сообщение и «Повторить».
- У студента уже есть необработанная заявка → форма открывается с её данными, кнопка — «Обновить
  заявку»; вторая заявка не создаётся.

**«Назад».** Системная кнопка и жест: форма заявки → шаг 3 → шаг 2 → профиль. Снятие фильтра по
региону — не отдельный экран: «Назад» с шага 3 без фильтра ведёт на шаг 2, а не к отфильтрованному
списку.

Сохранено: в профиле — ничего; на сервере — заявка (название, регион, автор).

**Расхождения с текущим поведением.**
- Формы заявки нет: «Моего университета нет в списке» сразу ведёт на финал «Профиль создан».
- Финала «Заявка отправлена» и строки о заявке в карточке профиля нет.
- Регион после «Искать по всем регионам» теряется (параметры экрана очищаются) — для заявки его
  нужно сохранить.
- Текст финала «Если его пока нет в списке — загляните позже» не говорит, что университет
  добавляет администратор.

**Решено: регионы без университетов на шаге 2 не помечаем** (2026-10-09). Пустых регионов на
стенде 2 из 89, `RegionDto` числа университетов не содержит, а пустой регион и так обрабатывается
на шаге 3. Вернуться, если по заявкам пустых регионов окажется заметно больше.

**Решено: прямой ссылки на заявку с пустого шага 3 нет** (2026-10-09). Порядок жёсткий: сначала
поиск по всем регионам, потом заявка. Университет может быть привязан к другому региону — прямая
ссылка дала бы ложные заявки и ожидание там, где университет уже есть в справочнике.

**Решено: уведомления о добавленном университете нет** (2026-10-09). Достаточно того, что
университет сам появляется в профиле (п. 10).

Открытых вопросов по сценарию не осталось
([#50](https://github.com/coungard/univer_mobile/issues/50)).

Статус: не проверено вживую (пустое состояние и поиск по всем регионам проверялись на пустом
результате поиска, а не на пустом регионе).

### Сценарий 2. Выбрал университет, но в нём нет факультетов

1. Шаги 2–3: регион → университет → «Далее». Университет сохраняется.
2. Шаг 4: «В этом университете пока нет факультетов. Университет сохранён в профиле». Кнопка
   «Далее» неактивна, выход — «Завершить без факультета».
3. Финальный экран «Профиль создан»: «Университет сохранён, факультет не выбран».
4. В профиле: университет и карточка «Завершить настройку — выберите факультет», которая
   открывает шаг 4. Если факультеты так и не появились, а университет выбран по ошибке, —
   «Изменить университет или группу» открывает мастер с шага 2.

Сохранено: университет.
Статус: проверено (Махачкалинский филиал ЮФУ).

Частый случай, а не исключение: факультетов нет у 87 из первых 200 университетов справочника.

### Сценарий 3. Выбрал факультет и курс, но на курсе нет групп

1. Шаги 2–4: регион → университет → факультет. Каждый выбор сохраняется по «Далее».
2. Шаг 5: курсы 1–5. У каждого подпись — «Групп: N» или «Групп пока нет», так что пустой курс
   виден ещё до выбора. Выбрать можно любой, в том числе пустой.
3. Шаг 6: «На N курсе пока нет групп. Факультет и курс сохранены в профиле». Выход — «Завершить
   без группы».
4. Финальный экран «Почти готово»: «Факультет и курс сохранены, осталась группа».
5. В профиле: университет, факультет, курс и карточка «Завершить настройку — выберите группу»,
   которая открывает шаг 6. При следующем запуске приложения шаг 6 откроется сам — если группа к
   тому времени появилась, студент выбирает её без администратора.

Сохранено: университет, факультет, курс.
Статус: проверено (ДГТУ → Факультет компьютерных технологий и энергетики → 3 курс).

Разновидность: группы на курсе есть, но нужной среди них нет — тот же путь через «Моей группы
нет в списке».

### Сценарий 4. Выбрал группу, но у неё нет расписания

1. Шаги 2–6 пройдены, группа выбрана — студент зачислен в неё сразу.
2. Финальный экран «Готово» → «Открыть расписание».
3. Экран расписания показывает «Расписание пока пусто», а текст и действие зависят от того,
   чего именно не хватает (логика `ScheduleScreen`, описана в `UI_UX.md`, раздел 6):

| Состояние расписания группы | Текст | Действие |
|---|---|---|
| расписание семестра не открыто | «…ещё не открыто администратором — загляните позже» | нет |
| открыто, занятий группы нет | «Заполните расписание своей группы…» | «Заполнить расписание группы» |
| занятия заполнены, но не сгенерированы | «Занятия по вашему расписанию ещё не сгенерированы» | «Перейти к генерации занятий» |
| согласовано, занятий группы нет | «…обратитесь к администратору» | нет |

Сохранено: всё. Мастер завершён, карточки «Завершить настройку» в профиле нет.
Статус: проверен третий вариант (ДГТУ → 1 курс → У530 РПиС до генерации занятий); остальные три
в рамках мастера не проверялись.

Замечание: финальный экран говорит «расписание уже доступно», хотя в этом сценарии его нет.
Мастер не знает о состоянии расписания группы в момент выбора — текст стоит смягчить
(«Вы в своей группе») либо проверять наличие занятий перед показом финала.

### Сценарий 5. Выбрал группу с готовым расписанием

1. Шаги 2–6 пройдены, группа выбрана.
2. Финальный экран «Готово» → «Открыть расписание».
3. Экран расписания сразу показывает текущую неделю с занятиями группы; тап по занятию
   открывает его карточку.
4. В профиле: университет, факультет, курс и группа. Карточки «Завершить настройку»
   нет; сменить выбор можно через «Изменить университет или группу».

Сохранено: всё.
Статус: проверено (ДГТУ → 1 курс → У530 РПиС, 295 занятий в семестре).

## 9. Создание отсутствующих сущностей: шаги X и Y

Решение 2026-10-08: если нужной сущности нет, студент не уходит на финальный экран с пустым
профилем, а **создаёт её сам** и идёт дальше. Флоу детализируется с конца — с группы, потому что
любая созданная выше сущность пуста и неизбежно приводит вниз по цепочке.

Уточнение 2026-10-09: это касается только группы и факультета. **Университет студент не
создаёт** — шаг Z отменён, см. 9.3.

| Шаг | Что создаёт | Когда предлагается | Куда ведёт |
|---|---|---|---|
| **X** | группу | на шаге 6 нет подходящей группы для выбранных факультета и курса | финал «Готово» |
| **Y** | факультет | на шаге 4 в выбранном университете нет подходящего факультета | курс → X |

Две точки входа, один хвост:

```
шаг 3 «Университет» ──нет──▶ заявка на университет ──▶ «Заявка отправлена»
шаг 4 «Факультет»   ──нет──▶ Y ──▶ шаг 5 «Курс» ─┐
шаг 6 «Группа»      ──нет──▶ X ◀─────────────────┘─▶ «Готово»
```

«Нет подходящей» — оба случая из 4.1: список пуст и нужной нет в непустом списке.

### 9.1. Шаг X — создание группы

**Вход.** Шаг 6, факультет и курс уже сохранены в профиле.
- Список пуст: вместо «На N курсе пока нет групп» — предложение создать группу, основная кнопка
  «Создать группу».
- Список не пуст: под списком ссылка «Моей группы нет в списке — создать».

**Форма.**

| Поле | Обязательное | Пример |
|---|---|---|
| Название группы (`name`) | да, до 64 символов | «У530» |
| Полная расшифровка названия (`fullName`) | нет, до 255 символов | «Разработка программных и информационных систем» |

Над формой — контекст только для чтения: университет, факультет, курс. Изменить их можно кнопкой
«Назад», а не в форме.

**Действие.** «Создать группу» → `POST /students/me/group` → группа создаётся на сервере, студент
сразу зачислен в неё (в ответе `StudentDto` с новым `groupId`) → финальный экран «Готово».
Семестр подбирает сервер; если учебного года или семестра нет — создаёт.

**Что дальше.** У только что созданной группы расписания нет, поэтому за шагом X всегда следует
сценарий 4 (раздел 8): пустой экран расписания с действием по состоянию семестра.

**Ошибки.**
- Группа с таким названием в этом семестре уже есть (`409`, `field: "name"`, сравнение без учёта
  регистра и крайних пробелов) → сообщение у поля и предложение выбрать существующую, а не общий
  тост. В ответе есть `id` существующей группы — выбор сохраняется через `PATCH /students/me`.
- Студент уже создал 3 группы (`422`) → сообщение с текстом сервера; остаётся выбрать группу из
  списка или завершить без группы.
- Ошибка сети → форма остаётся заполненной, «Повторить».
- Факультет исчез (`404`) → возврат на шаг 4 с сообщением, как сейчас в `useSaveSetupStep`.

**Исправление опечатки.** `PUT /students/me/group` меняет название и расшифровку, пока студент
сам создал группу и он в ней один; иначе `422`. Где это в приложении (профиль?) — решить при
детализации.

### 9.2. Шаг Y — создание факультета

**Вход.** Шаг 4, университет уже сохранён в профиле.
- Список пуст: вместо «В этом университете пока нет факультетов» — предложение создать факультет.
- Список не пуст: под списком ссылка «Моего факультета нет в списке — создать».

**Форма.** Одно поле — название факультета (`name`, до 255 символов; например,
«Экономический»). Над формой — университет.

**Действие.** «Создать факультет» → `POST /students/me/faculty` → факультет создаётся и сразу
сохраняется в профиле (курс и группа в профиле сбрасываются) → шаг 5 «Курс» → шаг X.

Курс остаётся между Y и X: группа привязана к курсу, а знает его только студент. У нового
факультета групп нет ни на одном курсе, поэтому после выбора курса шаг 6 со списком
пропускается — сразу открывается форма шага X.

**Ошибки.** Те же: дубль названия в этом университете (`409` с `id` существующего факультета),
лимит в 3 созданных факультета (`422`), сеть, исчезнувший университет (возврат на шаг 3).
Опечатку исправляет `PUT /students/me/faculty` — пока факультет создан этим студентом и никто
другой его не выбрал.

### 9.3. Университет: студент не создаёт

Решение 2026-10-09: шаг Z отменён, B11 ([univer#88](https://github.com/coungard/univer/issues/88))
закрыта без реализации. Справочник университетов ведёт только администратор.

Вместо создания — **заявка на добавление университета** (решение 2026-10-09, B13 + M15):
- в регионе нет университетов → «Искать по всем регионам»;
- поиск по всем регионам не помог → «Моего университета нет в списке» → форма заявки (название,
  регион) → финал «Заявка отправлена»;
- администратор добавляет университет и закрывает заявку — университет сам появляется в профиле
  автора, и мастер продолжается с шага 4.

Сценарий расписан по шагам в разделе 8 (сценарий 1); нерешённые вопросы — там же и в
[#50](https://github.com/coungard/univer_mobile/issues/50).

### 9.4. Общее для X и Y

- **«Пропустить» остаётся.** Создание — предложение, а не обязанность: на каждой форме есть
  «Завершить без группы / факультета», которая ведёт на прежний финальный экран.
  Первокурсник, не знающий своей группы, не должен её придумывать.
- **Каждый шаг сохраняется сразу.** Создал факультет и закрыл приложение — при следующем
  запуске мастер откроется на шаге «Курс», а не с начала. Это следует из раздела 3 и уже работает
  для выбора из списка.
- **«Назад» с формы** возвращает на список того же шага без потери уже сохранённого выше.
- **Созданное видно всем сразу**, без подтверждения администратором. Следующий студент того же
  университета находит факультет и группу в списке и просто выбирает их. Созданное студентом
  отличает поле `createdByStudentId` в `FacultyDto` и `GroupDto`.
- **Лимит:** один студент создаёт не больше 3 факультетов и 3 групп, четвёртая попытка — `422`.
- **Проверка на клиенте:** название не пустое, без ведущих и хвостовых пробелов; длина — до 64
  символов у группы, до 255 у расшифровки и у факультета.

### 9.5. Как меняются сценарии раздела 8

| # | Было | Станет |
|---|---|---|
| 1 | поиск по стране → финал «Профиль создан» | поиск по стране → заявка на университет → «Заявка отправлена» (9.3) |
| 2 | финал «Профиль создан» | Y → курс → X → «Готово» |
| 3 | финал «Почти готово» | X → «Готово» |
| 4 | без изменений; сюда же попадает каждый, кто прошёл X | |
