## 1. Цель

Вместо одной формы с пикером университета — мастер из шести шагов, который приводит студента
сразу в свою группу и к расписанию, без ручного назначения группы администратором.

| # | Шаг | Что выбирает | Зависит от |
|---|---|---|---|
| 1 | Личные данные | логин, имя, фамилия, email, пароль, дата рождения | — (экран уже есть) |
| 2 | Регион | регион РФ | — |
| 3 | Университет | ВУЗ выбранного региона | регион |
| 4 | Факультет | факультет выбранного ВУЗа | университет |
| 5 | Курс | 1–5 | факультет |
| 6 | Группа | группа факультета на выбранном курсе | факультет + курс |

**Главное требование:** на любом шаге со 2-го по 6-й нужной сущности может не оказаться.
Студент не должен упираться в тупик — см. раздел 4.

Регистрация преподавателя в этот спринт не входит (см. открытый вопрос 6.4).

## 2. Что есть сейчас

**Приложение**
- `RegisterStudentScreen` — одна форма: личные данные + поиск университета по всей стране
  (`SearchableSelectField`, `useUniversitiesQuery`) → `POST /students/register`.
- После регистрации приложение само входит под новым пользователем (`loginWithPassword`) и
  открывает профиль. Значит, шаги после первого могут выполняться уже с токеном.
- Профиль студента без группы показывает «Группа ещё не назначена. Обратитесь к администратору».

**Бэкенд — что мешает мастеру**
- **Регионы уже есть (issue #80 бэкенда).** `GET /regions` — публичный справочник 89 субъектов
  РФ, `GET /universities?regionId=` — фильтр, `regionId` обязателен у каждого ВУЗа. В регионе
  может не быть ни одного ВУЗа.
- **Много ВУЗов без факультетов** (87 из первых 200) — пустой шаг 4 будет частым случаем, а не
  исключением.
- **Группа не привязана к факультету напрямую.** Цепочка: группа → семестр → учебный год
  (`yearNumber` — это и есть «курс») → программа → факультет. Шага «программа» в мастере нет,
  поэтому «группы факультета на N-м курсе» — это обход всех программ факультета.
- **Справочники ниже факультета закрыты.** `programs`, `study-years`, `semesters`, `groups`
  без токена отвечают `401`; публичны только университеты, факультеты и кафедры.
- **Студент не может сам выбрать группу.** `RegisterStudentRequest` не принимает `groupId`,
  а `PUT /students/{id}` доступен только `ADMIN`.
- **`universityId` обязателен при регистрации** — зарегистрироваться, не найдя свой ВУЗ, нельзя.
- **Факультет и курс негде хранить.** У `StudentDto` есть только `universityId` и `groupId`;
  если группы нет, выбранные факультет и курс теряются.

## 3. Ключевое решение: когда создаётся аккаунт

**Рекомендация — аккаунт создаётся на шаге 1, шаги 2–6 идут уже под токеном.**

1. Шаг 1 → `POST /students/register` (без университета) → автовход.
2. Шаги 2–6 — «настройка профиля»: каждый выбор сохраняется на сервере.
3. Пока профиль не заполнен, приложение при входе открывает мастер с первого незаполненного шага.

Почему так:
- **Отсутствующая сущность перестаёт быть проблемой регистрации.** Аккаунт уже есть, профиль
  валиден при любой степени заполненности, мастер можно продолжить позже.
- **Занятый логин или email (`409`) виден сразу**, а не после шести экранов.
- **Закрытые справочники не нужно открывать публично** — под токеном они уже доступны.
- **Переживает закрытие приложения** — прогресс хранится на сервере, а не в памяти.

Цена: появляются аккаунты с незаполненным профилем, и нужно снять обязательность `universityId`.

Альтернатива — копить выбор локально и отправить один запрос в конце. Тогда нужно открыть
публично все справочники до групп, добавить `groupId` в `RegisterStudentRequest`, а случай
«сущности нет» всё равно потребует необязательных полей. Выигрыша не даёт.

## 4. Отсутствующие сущности

### 4.1. Какие бывают «нет»

| Вид | Пример | Как отличить |
|---|---|---|
| **Список пуст** | у ВУЗа нет факультетов; на 3-м курсе нет групп | `200` и `totalElements == 0` |
| **Нужного нет в списке** | факультет есть, но не мой | решает пользователь: «Нет в списке» |
| **Регион без ВУЗов** | в справочнике 89 регионов, ВУЗы есть не в каждом | `200` и пустой список на шаге 3 |
| **Не знаю / позже** | первокурсник ещё не знает группу | кнопка «Пропустить» |
| **Ошибка загрузки** | нет сети, `5xx` | **не** пустой список — экран ошибки с «Повторить» |
| **Сущность исчезла** | группу удалили между выбором и сохранением | `404`/`422` при сохранении |

Пустой список и ошибка загрузки обязаны выглядеть по-разному: сейчас часть экранов при сбое
показывает просто пустоту, здесь это привело бы к ложному «вашего ВУЗа нет».

### 4.2. Общее правило

Шаги зависят друг от друга по цепочке, поэтому **если на шаге N сущности нет — шаги N+1…6
пропускаются**, а не показываются пустыми:

1. Сохраняется всё выбранное до шага N−1.
2. Студент попадает на финальный экран, где сказано, чего именно не хватает и что будет дальше.
3. В профиле появляется карточка «Завершить настройку», которая открывает мастер с шага N.
4. По желанию студент оставляет заявку: «Моего факультета нет — ФКТИ» (свободный текст).

На каждом шаге 2–6 одинаковый набор действий: выбрать из списка, «Нет в списке», «Пропустить»,
«Назад».

### 4.3. По шагам

| Шаг | Нет сущности, когда… | Что показываем | Что сохранено | Куда дальше |
|---|---|---|---|---|
| 2. Регион | региона нет в списке; список не загрузился | «Нет в списке» → поиск ВУЗа по всей стране | ничего | шаг 3 без фильтра по региону |
| 3. Университет | в регионе нет ВУЗов; моего нет; ВУЗ привязан к другому региону | пустое состояние + «Искать по всем регионам» + «Нет в списке» | регион | поиск по стране → шаг 4, либо финал |
| 4. Факультет | у ВУЗа нет факультетов; моего нет | «В этом ВУЗе пока нет факультетов» + заявка | регион, ВУЗ | финал |
| 5. Курс | на факультете нет программ или учебных годов | курсы без групп помечены; выбрать можно любой | регион, ВУЗ, факультет | шаг 6 (возможно, пустой) |
| 6. Группа | на курсе нет групп; моей нет; не знаю группу | «Групп пока нет» + заявка | всё, кроме группы | финал |

Отдельные случаи:
- **Регион — единственный шаг, где «нет» не останавливает мастер.** Регион нужен только как
  фильтр, поэтому без него шаг 3 превращается в нынешний поиск по всей стране. Этим же
  закрывается случай, когда ВУЗ привязан не к тому региону, где его ищет студент.
- **Курс выбирается всегда из 1–5**, даже если учебных годов в данных нет: это знание самого
  студента, оно пригодится администратору при назначении группы.
- **Смена выбора выше по цепочке сбрасывает всё ниже.** Вернулся на шаг 3 и сменил ВУЗ —
  факультет, курс и группа очищаются, в том числе на сервере.
- **Сущность исчезла при сохранении** — возврат на этот шаг с сообщением и перезагрузкой списка,
  а не общий тост об ошибке.

### 4.4. Финальный экран и профиль

Финал зависит от того, докуда дошёл студент:

| Заполнено до | Заголовок | Текст |
|---|---|---|
| группы | «Готово» | сразу открывается расписание |
| курса | «Почти готово» | «Группа появится, когда её добавит администратор» |
| ВУЗа | «Профиль создан» | «Факультета пока нет в списке — мы сообщим администратору» |
| ничего | «Профиль создан» | «Вашего ВУЗа пока нет в списке» |

Текущий текст профиля «Обратитесь к администратору» заменяется на карточку «Завершить
настройку» с указанием первого незаполненного шага. Когда недостающая сущность появится на
бэкенде, студент доходит мастер сам — без администратора.

## 6. Открытые вопросы

1. ✅ **Решено (2026-10-08): студент может сам записаться в любую группу**, без подтверждения
   администратором.
2. **Что такое «текущий семестр»** при поиске групп: по датам `startDate`…`endDate` или по
   явному признаку? Что показывать между семестрами?
3. **Курс 1–5 или по факту?** В магистратуре курсов два, у специалитета бывает шесть. Жёстко
   1–5 или диапазон из учебных годов факультета?
4. **Преподаватель.** Нужен ли ему такой же мастер (регион → ВУЗ → факультет → кафедра)?
   Сейчас форма не отправляет `departmentId`, хотя `API.md` называет его обязательным, —
   регистрация при этом проходит.
5. **Нужна ли заявка «Нет в списке» в этом спринте** (B7 + M8) или достаточно завершать мастер?
6. **Можно ли менять ВУЗ, факультет и группу после завершения мастера** из профиля?

## 7. Критерии готовности

- [ ] Новый студент проходит шаги 1–6 и сразу видит расписание своей группы.
- [ ] Регион не найден → поиск ВУЗа по всей стране работает.
- [ ] В регионе нет ВУЗов → пустое состояние, поиск по стране, «Нет в списке».
- [ ] У ВУЗа нет факультетов → финал «Профиль создан», ВУЗ сохранён.
- [ ] На курсе нет групп → финал «Почти готово», факультет и курс сохранены.
- [ ] «Пропустить» на каждом из шагов 2–6 приводит к профилю без ошибок.
- [ ] Обрыв сети на любом шаге даёт экран ошибки с «Повторить», а не пустой список.
- [ ] Закрытие приложения посреди мастера → при следующем входе мастер открывается с того же шага.
- [ ] Смена ВУЗа на шаге 3 очищает факультет, курс и группу.
- [ ] Карточка «Завершить настройку» в профиле открывает первый незаполненный шаг.
- [ ] Занятый логин или email показывается на шаге 1.
- [ ] `tsc` и `eslint` проходят.
